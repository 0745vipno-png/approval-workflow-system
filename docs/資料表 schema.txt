一、命名規則建議

規則

資料表：使用複數小寫，例如 users
主鍵：xxx_id
外鍵：對應主表主鍵名稱
時間欄位：
created_at
updated_at
狀態欄位：status
布林欄位：is_xxx
二、資料表 Schema

1. departments
用途

儲存部門資料

CREATE TABLE departments (
    department_id      BIGINT PRIMARY KEY AUTO_INCREMENT,
    department_name    VARCHAR(100) NOT NULL,
    status             VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    created_at         DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at         DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE (department_name)
);

欄位說明

| 欄位              | 型別           | 限制               | 說明                |
| --------------- | ------------ | ---------------- | ----------------- |
| department_id   | BIGINT       | PK               | 部門主鍵              |
| department_name | VARCHAR(100) | NOT NULL, UNIQUE | 部門名稱              |
| status          | VARCHAR(20)  | NOT NULL         | ACTIVE / INACTIVE |
| created_at      | DATETIME     | NOT NULL         | 建立時間              |
| updated_at      | DATETIME     | NOT NULL         | 更新時間              |


2. users
用途

儲存使用者基本資料。

CREATE TABLE users (
    user_id             BIGINT PRIMARY KEY AUTO_INCREMENT,
    employee_no         VARCHAR(30) NOT NULL,
    name                VARCHAR(100) NOT NULL,
    email               VARCHAR(150) NOT NULL,
    password_hash       VARCHAR(255) NOT NULL,
    department_id       BIGINT NOT NULL,
    account_status      VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE (employee_no),
    UNIQUE (email),
    CONSTRAINT fk_users_department
        FOREIGN KEY (department_id) REFERENCES departments(department_id)
);

欄位說明

| 欄位             | 型別           | 限制               | 說明                         |
| -------------- | ------------ | ---------------- | -------------------------- |
| user_id        | BIGINT       | PK               | 使用者主鍵                      |
| employee_no    | VARCHAR(30)  | NOT NULL, UNIQUE | 教職員編號                      |
| name           | VARCHAR(100) | NOT NULL         | 姓名                         |
| email          | VARCHAR(150) | NOT NULL, UNIQUE | 登入帳號                       |
| password_hash  | VARCHAR(255) | NOT NULL         | 密碼雜湊                       |
| department_id  | BIGINT       | FK, NOT NULL     | 所屬部門                       |
| account_status | VARCHAR(20)  | NOT NULL         | ACTIVE / INACTIVE / LOCKED |
| created_at     | DATETIME     | NOT NULL         | 建立時間                       |
| updated_at     | DATETIME     | NOT NULL         | 更新時間                       |

4. user_roles

用途

管理使用者與角色的多對多關係。

CREATE TABLE user_roles (
    user_role_id        BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id             BIGINT NOT NULL,
    role_id             BIGINT NOT NULL,
    assigned_at         DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    assigned_by         BIGINT,
    UNIQUE (user_id, role_id),
    CONSTRAINT fk_user_roles_user
        FOREIGN KEY (user_id) REFERENCES users(user_id),
    CONSTRAINT fk_user_roles_role
        FOREIGN KEY (role_id) REFERENCES roles(role_id),
    CONSTRAINT fk_user_roles_assigned_by
        FOREIGN KEY (assigned_by) REFERENCES users(user_id)
);

欄位說明

| 欄位           | 型別       | 限制           | 說明   |
| ------------ | -------- | ------------ | ---- |
| user_role_id | BIGINT   | PK           | 對應主鍵 |
| user_id      | BIGINT   | FK, NOT NULL | 使用者  |
| role_id      | BIGINT   | FK, NOT NULL | 角色   |
| assigned_at  | DATETIME | NOT NULL     | 指派時間 |
| assigned_by  | BIGINT   | FK           | 由誰指派 |


5. manager_mapping
用途

維護員工與直屬主管對應。

CREATE TABLE manager_mapping (
    mapping_id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    employee_id         BIGINT NOT NULL,
    manager_id          BIGINT NOT NULL,
    effective_start     DATE NOT NULL,
    effective_end       DATE,
    status              VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    created_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT fk_manager_mapping_employee
        FOREIGN KEY (employee_id) REFERENCES users(user_id),
    CONSTRAINT fk_manager_mapping_manager
        FOREIGN KEY (manager_id) REFERENCES users(user_id),
    CONSTRAINT chk_employee_not_self_manager
        CHECK (employee_id <> manager_id)
);

補充規則

同一時間同一員工應只有一筆 ACTIVE 的主管對應

這個規則可用程式或資料庫 unique 條件控制

| 欄位              | 型別          | 限制           | 說明                |
| --------------- | ----------- | ------------ | ----------------- |
| mapping_id      | BIGINT      | PK           | 關聯主鍵              |
| employee_id     | BIGINT      | FK, NOT NULL | 員工                |
| manager_id      | BIGINT      | FK, NOT NULL | 主管                |
| effective_start | DATE        | NOT NULL     | 生效起日              |
| effective_end   | DATE        | NULL         | 生效迄日              |
| status          | VARCHAR(20) | NOT NULL     | ACTIVE / INACTIVE |
| created_at      | DATETIME    | NOT NULL     | 建立時間              |
| updated_at      | DATETIME    | NOT NULL     | 更新時間              |


6. requests
用途

申請單主表，整個簽核系統核心。

CREATE TABLE requests (
    request_id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    request_no              VARCHAR(50) NOT NULL,
    applicant_id            BIGINT NOT NULL,
    request_type            VARCHAR(50) NOT NULL,
    title                   VARCHAR(200) NOT NULL,
    content                 TEXT NOT NULL,
    start_date              DATE,
    end_date                DATE,
    status                  VARCHAR(50) NOT NULL,
    current_step            VARCHAR(50) NOT NULL,
    current_approver_id     BIGINT,
    submitted_at            DATETIME,
    approved_at             DATETIME,
    cancelled_at            DATETIME,
    created_at              DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at              DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE (request_no),
    CONSTRAINT fk_requests_applicant
        FOREIGN KEY (applicant_id) REFERENCES users(user_id),
    CONSTRAINT fk_requests_current_approver
        FOREIGN KEY (current_approver_id) REFERENCES users(user_id),
    CONSTRAINT chk_requests_date_range
        CHECK (end_date IS NULL OR start_date IS NULL OR start_date <= end_date)
);

建議狀態值
DRAFT
PENDING_MANAGER
RETURNED_BY_MANAGER
REJECTED_BY_MANAGER
PENDING_HR
RETURNED_BY_HR
REJECTED_BY_HR
APPROVED
CANCELLED

欄位說明

| 欄位                  | 型別           | 限制               | 說明                         |
| ------------------- | ------------ | ---------------- | -------------------------- |
| request_id          | BIGINT       | PK               | 申請單主鍵                      |
| request_no          | VARCHAR(50)  | NOT NULL, UNIQUE | 單號                         |
| applicant_id        | BIGINT       | FK, NOT NULL     | 申請人                        |
| request_type        | VARCHAR(50)  | NOT NULL         | 請假、報銷等                     |
| title               | VARCHAR(200) | NOT NULL         | 申請標題                       |
| content             | TEXT         | NOT NULL         | 申請內容                       |
| start_date          | DATE         | NULL             | 起始日期                       |
| end_date            | DATE         | NULL             | 結束日期                       |
| status              | VARCHAR(50)  | NOT NULL         | 當前狀態                       |
| current_step        | VARCHAR(50)  | NOT NULL         | DRAFT / MANAGER / HR / END |
| current_approver_id | BIGINT       | FK               | 當前簽核人                      |
| submitted_at        | DATETIME     | NULL             | 送出時間                       |
| approved_at         | DATETIME     | NULL             | 核准完成時間                     |
| cancelled_at        | DATETIME     | NULL             | 撤回時間                       |
| created_at          | DATETIME     | NOT NULL         | 建立時間                       |
| updated_at          | DATETIME     | NOT NULL         | 更新時間                       |

7. approval_logs
用途

記錄簽核歷程與狀態轉換。

CREATE TABLE approval_logs (
    log_id               BIGINT PRIMARY KEY AUTO_INCREMENT,
    request_id           BIGINT NOT NULL,
    action_by            BIGINT NOT NULL,
    action_role          VARCHAR(30) NOT NULL,
    from_status          VARCHAR(50),
    to_status            VARCHAR(50) NOT NULL,
    action_type          VARCHAR(30) NOT NULL,
    comment              TEXT,
    action_time          DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_approval_logs_request
        FOREIGN KEY (request_id) REFERENCES requests(request_id),
    CONSTRAINT fk_approval_logs_action_by
        FOREIGN KEY (action_by) REFERENCES users(user_id)
);

action_type 建議值
SAVE_DRAFT
SUBMIT
APPROVE
RETURN
REJECT
CANCEL
RESUBMIT

| 欄位          | 型別          | 限制           | 說明    |
| ----------- | ----------- | ------------ | ----- |
| log_id      | BIGINT      | PK           | 紀錄主鍵  |
| request_id  | BIGINT      | FK, NOT NULL | 所屬申請單 |
| action_by   | BIGINT      | FK, NOT NULL | 操作人   |
| action_role | VARCHAR(30) | NOT NULL     | 操作角色  |
| from_status | VARCHAR(50) | NULL         | 原狀態   |
| to_status   | VARCHAR(50) | NOT NULL     | 新狀態   |
| action_type | VARCHAR(30) | NOT NULL     | 動作類型  |
| comment     | TEXT        | NULL         | 意見    |
| action_time | DATETIME    | NOT NULL     | 操作時間  |


8. notifications

CREATE TABLE notifications (

9. attachments

用途

CREATE TABLE attachments (

五、狀態與步驟欄位建議

現在有兩個很重要的欄位：

status

表示案件現在的實際狀態

例如：

PENDING_MANAGER
RETURNED_BY_HR
current_step

表示流程目前所在階段

例如：

DRAFT
MANAGER_REVIEW
HR_REVIEW

為什麼兩個都留？

因為：

status 比較細，給系統邏輯判斷

八、幾個實作上很重要的提醒

1. 不要把角色直接寫死在 users

用 user_roles 比較正確，因為一人可能多角色。

2. 不要只靠 requests.status 看歷史

一定要有 approval_logs。

3. current_approver_id 很重要

待簽核清單通常就是靠它查。

4. request_no 要獨立

不要只顯示 request_id，因為使用者看到單號比較直覺。

可以做成像：

REQ202604140001
