四、最重要的三條主資料流

這三條通常是老師最容易看懂，也最該放進報告的。

1. 申請送出資料流

Requester
→ 填寫申請表單
→ P2 申請單管理
→ 寫入 requests
→ 查詢 manager_mapping
→ 設定 current_approver_id
→ 寫入 approval_logs
→ 觸發 P4 通知處理
→ 通知 Manager

對應資料表
requests
manager_mapping
approval_logs
notifications

2. 主管簽核資料流

Manager

→ 開啟待簽核案件
→ P3 簽核流程處理
→ 讀取 requests
→ 驗證 user_roles / current_approver_id
→ 更新 requests.status
→ 寫入 approval_logs
→ 觸發 P4 通知處理
→ 通知 HR 或 Requester

對應資料表
requests
user_roles
approval_logs
notifications

3. HR 最終核定資料流

HR
→ 開啟待核定案件
→ P3 簽核流程處理
→ 讀取 requests
→ 驗證角色與狀態
→ 更新 requests.status = APPROVED / RETURNED_BY_HR / REJECTED_BY_HR
→ 寫入 approval_logs
→ 觸發 P4 通知處理
→ 通知 Requester

六、Data Flow 邏輯重點

設計說明

1. requests 是主資料流核心

所有申請狀態都圍繞 requests 這張表轉。

2. approval_logs 是歷程流核心

每次動作都必須記錄，才能做：

進度追蹤
歷程查詢
稽核
3. manager_mapping 決定流程流向

申請送出後，系統不是隨機送件，而是透過主管對應表決定下一位處理者。

4. notifications 是事件導向的延伸流

通知不是主流程本身，但會被主流程觸發。
