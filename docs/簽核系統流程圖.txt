六、你要先決定的重要規則（很關鍵）

這些規則會影響流程圖與程式邏輯。

規則 1：HR 退回後要回哪裡？
方案 A：回主管重簽
Requester → Manager → HR → Returned
Requester 修改後
→ Manager → HR
方案 B：直接回 HR
Requester → Manager → HR → Returned
Requester 修改後
→ HR

規則 2：申請人可否撤回？

情境： 申請人剛按下「撤回」，結果同時主管也按下了「同意」

開發防護： 撤回 API 必須使用 DB Transaction。在更新狀態為 Cancelled 前，必須先 SELECT ... FOR UPDATE 檢查 status 是否依然是 Pending。如果狀態已經變成了 Pending_HR，就要報錯告訴申請人：「主管已簽核，無法撤回」。

例如主管尚未看時：

Pending → Cancelled

建議允許，但要限制條件。

規則 3：主管多久沒簽要提醒？

例如：

超過 3 天寄通知
Dashboard 顯示逾期件數
